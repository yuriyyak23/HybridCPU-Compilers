# 96 — Validation proportional to change

Existing harness owners: ManagedPortSmoke, CompilerProfileSmoke, SchedulerBenchmark, Native/compiler contract and ReleaseQualification tools. Extend these; no permanent second framework just for v3.

| Change | Minimum meaningful validation |
|---|---|
| Docs | current source facts, local links, manifest/checksums consistency |
| Ownership/stage extraction | affected Release + existing harness + old/new bounded bytes/annotations/relocations/diagnostics |
| Semantic/lowering defect | actual before/after production path; physical operands and serialized bytes |
| Shared managed/compiler path | full ManagedPortSmoke for touched contracts |
| Roslyn language/admission | existing companion positive/negative/fault/cancel/oracle controls and applicable managed corpus |
| Policy/profile/cache | off baseline equality, deterministic keys/selection, stale/corrupt/version/reference/options negatives |
| Release parser/admission | actual public/CLI routing and precedence, no output before success |
| Runtime/publish claim | corresponding pack/ABI/loader/corruption/current runtime/publish contracts |

Existing malformed PE/metadata/EH/generic/session controls and Read/Choose emitted-CIL oracle are applicable scoped results. Add fuzz/property/metamorphic cases for a real coverage gap; deterministic seeds/budgets/minimized repro, not universal no-error/no-hang assertions.

Source map presence/trivia/source paths may change PDB/provenance while code stays equal. Different frontend facts may permit semantic rather than byte equivalence; declare relation before test.

Cross-root, N-thread and cold/warm cache matrix only for corresponding implemented/claimed modes. Observers off/on must not select output; profile changes may only affect statically admissible candidates.

Synthetic phase parser fixtures never prove execution/publication. Frozen binary stability never validates changed source or guest completion. No mandatory multi-day run, fresh pack or repeated clean publish for compiler-only extraction.

New outputs/logs/cache/obj/bin/TEMP/TMP/CLI home/packages stay in fresh iteration path. Before heavy build/publish/guest action, verify active processes using executable/start/command; never stop or duplicate existing guest.

## Proof workloads помимо Visual Studio

При необходимости разрешены existing CLI smoke, source→image, independent scalar/encoded-byte oracle, bounded scheduler benchmark и diagnostic runtime/loader нагрузки по затронутому contract. Выбирать нагрузку по проверяемому свойству и actual consumer; она дополняет VS tests, не заменяет реализацию и не требует отдельной campaign для обычного compiler slice.

Default/SDK source lanes собирать в разных isolated roots с matching Roslyn references; проверять actual TargetPath/obj/bin. Если используется временный snapshot тестового проекта, сохранить реальные compile/assembly policies (в частности GlobalSuppressions.cs отключает test parallelism из-за shared registry) и назвать fresh/reused dependency identities. Targeted snapshot не объявлять full project/solution acceptance.

Wide-rem checkpoint диагностирован как Debug-specific CFG/epilogue byte mismatch. Сохранять Release exact equality и independent serialized quotient/MUL/SUB ABI/clobber/result/fault oracle; full Debug acceptance не заявлена.
