# CompilerFacts v1 — software compiler facts, not hardware

`CompanionBridgeProjectionV1` is compiled only by `HardwareBridge.Companion.csproj`, because the parent project does not directly reference the Roslyn/CIL projects. The sidecar project explicitly references **existing** `HybridCPU.Compiler.Roslyn` and projects only `ManagedSourceBodyWorldResultV1`; it does not create a second compiler/importer. No HWIR, RTL, Verilog, CIRCT, hardware binding resolver or EDA bridge exists here.

`Project` emits `Candidate` only for a successful **software** StandaloneRestrictedModule graph with exact roots, owned PE module hashes, admitted method imports, closed method identities and independently re-checked **primary** source maps/PDB. Missing graph, analyzer failure, ambiguous root, stale PE/PDB, unowned body, partial closure or oversize lists yields `Rejected` with a diagnostic (or a fail-closed exception for malformed caller objects). Primary PDB mapping is never asserted for dependency modules; metadata-only references are not body owners. Root selectors include tokens and generic arguments where supplied; absent token overload selection remains the authority of the existing CIL importer.

Facts expose Companion `SourceInputDigest` and distinct output PE/PDB hashes. They are reported by Companion, **not self-attested evidence**. VLIW IR is not a hardware netlist. Hardware qualification, clock/latency/reset/memory contracts, target binding and independent evidence remain wholly external.

## Lifecycle and exact identities

`CompileBodyWorld` validates the incoming request, deep-copies references, roots and role lists, snapshots again and compares the two digests before one owned Companion call. Callers must keep inputs stable throughout transfer. `ManagedSourceCompanionV1` snapshots and admits source using Roslyn and analyzers, emits portable PE/PDB in memory, and calls `RestrictedCilImporterV1.ImportBodyWorld` with the selected owned-body and metadata-only sets. Source admission checks the supported managed subset, including NoHeap rules and bounded owned scalar constructors. Projected software success is an input to independent hardware admission.

`Project` binds each selected root to one imported method. Method facts carry stable identity, assembly/module, declaring type, method/signature, MethodDef token and identity/PE hash. Direct edges name caller/callee with IL offset and token. Endpoints must be in the admitted owned graph and direct callee lists must agree with projected edges. Token numbers alone cannot identify a method across modules. Source-map rows additionally pin method identity/token, PE/PDB hashes and IL/IR coordinates. Primary maps are independently recreated from the exact primary PE/PDB. Dependency PEs do not inherit the primary PDB. See [projection](CompanionBridgeProjectionV1.cs) and [DTO fields](BridgeCompilerFactsV1.cs).

## Digest domains

| Identity / owner | Exact byte domain and canonical order | Freshness and evidentiary limit |
| --- | --- | --- |
| SnapshotDigest / Bridge snapshot | SHA-256 uppercase of compact default `System.Text.Json` UTF-8 in DTO order excluding its digest, using ordered document/reference/root and role arrays. Text and references contribute SHA-256/size, not embedded contents | Recheck self-consistency and compare an independently expected live digest. Source identity only |
| SourceInputDigest / Roslyn Companion | SHA-256 uppercase of ordered compact UTF-8 JSON: schema, assembly name, admission policy, actual Roslyn assembly version, software compiler version, policy string, ordered `Documents[{VirtualPath,Sha256}]` and `References[sha256]`. For C#15, further hash ordered `Schema,SourceDigest,SdkHost` (assembly metadata). When owned scalar-constructor admission applies, hash snake_case compact `schema,source,body_reference_indices` with sorted selected body indices and lowercase hex | Reported input identity, tied to the actual Companion path. Does not certify executed external Csc or equal the Bridge snapshot |
| PayloadSha256 / v1 and provenance v2 codecs | SHA-256 uppercase of the exact compact UTF-8 serialized payload of that version, separately for each envelope | Rehash received bytes and independently verify live pins. Checksums carry no signing identity |
| PeSha256 / PdbSha256 / projected output | SHA-256 of exact emitted PE and portable PDB byte arrays. Bridge v1 top-level and provenance v2 use uppercase; internal CIL module/import provenance uses lowercase. Keep each field's own contract | Rehash actual buffers and check assembly/MethodDef/PDB owner. Digests establish output byte identity, not the executed tool or correctness |
| CoreIndexSha256 / HB provenance v2 | Uppercase SHA-256 of entire exact CW v2 index bytes including roots/descriptors | Independently supplied full index pin checks roots and shape |
| ClosureSha256 / CW v2 | Uppercase SHA-256 of concatenated ordered raw chunks including LF, with no extra separators; indexed file bytes are separately pinned by each row | Compare independently expected closure and rehash actual file/chunk bytes. Root selectors are outside this preimage |
| CscSha256 / CscOptionsSha256 / HB v2 evidence | Uppercase SHA-256 of supplied compiler image and exact supplied UTF-8 options bytes respectively. Executed link uses its own canonical ordered argv bytes and invocation/output-pair domains | Pin actual image, SDK, options and inputs independently. Supplied bytes can be accurate without proving a process consumed them |
