# HB-INT-04 — Golden raw trace interchange v1

Status: **implemented producer-only structural contract; independent Core qualification BLOCKED**. Owner: HardwareBridge `GoldenOracle/GoldenRawTraceV1.cs`. Version: `hybridcpu.hardwarebridge.golden-raw-trace/v1`; separate from existing `hybridcpu.hardwarebridge.sidecar/v1` and `golden-observation/v1`. No implicit migration of sidecar/v1.

## Trust and process boundary

`GoldenRawTraceCodecV1.Capture` accepts pre-recorded, host-provided source documents, compiled assembly **bytes** and ordered raw step observations. It does **not** run Golden code, load assemblies, select a delegate, resolve filesystem paths or start a process. `Observed` means only *caller provided a structurally consistent raw recording*, never independent source attestation, correctness oracle, comparison with RTL, AcceptedRtl or Verified.

A caller must supply an externally reviewed source snapshot and complete raw original source bytes in the snapshot's exact document order; the codec checks per-document SHA-256/size. Assembly byte SHA-256 is computed locally from the explicit byte buffer (maximum 32 MiB); this is not evidence that the bytes are executable PE, match the source compilation, or came from a trusted build. SourceSnapshotDigest, OriginalSourceSetSha256, CompiledAssemblySha256 and ReplayIdentity are distinct. A self-hash is not a signature. Reject if any original source bytes differ, if the snapshot is stale or if the independently expected assembly hash differs.

The root is a zero-based `RootIndex` into `BridgeSourceSnapshotV1.Roots`, **not** a method/assembly name to execute. Host software observation scope is exactly `raw-host-steps`. Requests for `cpu-cycle`, `rank4` or any other temporal/CPU scope yield `Blocked / HB4001`: reset polarity, logical clock to hardware edge, stall, memory arbitration/port, retire ordering authority and rank4 are not established by this interchange.

## Canonical model

`GoldenRawTraceV1` carries schema, scope, status/diagnostic, snapshot hash, original document identity rows and their aggregate hash, compiled assembly hash, root index, host-reported `ClockDomain`, context/lane cardinalities, ordered `InitialState`, ordered steps, and ReplayIdentity SHA-256. `GoldenTraceStepV1` carries Index (contiguous from zero), strictly increasing nonnegative host-reported LogicalClock (NOT a physical clock-cycle proof), ClockDomain (must match envelope), Context, Lane, `Before` / `After` state cells, explicit `Inputs` and `Outputs`, ordered `Events`, pinned ExpectedEventCount and ExpectedEventsSha256, and explicit `Choices` of nondeterministic values selected from a finite allowlist.

State is a bounded, named *selected projection*, not full CPU state. Ordered state cells must retain identical names, widths and signed flags from Before to After. Each next Before equals prior After exactly. A state cell and input/output cell is a `GoldenWordV1` (`Width` = 8/16/32/64, `Signed` boolean, unsigned-decimal `Bits` without forbidden high bits): 2's-complement bit pattern is never converted to an arithmetic signed JSON number. `Signed` is interpretation only. No hidden resets/state initialization.

Events are `MemoryRead` or `MemoryWrite` (explicit address/value), or `Retire` (explicit retire ID); event `Order` is exactly 0..N-1 **within a step**, context/lane match the step, no silent sort, no implicit memory arbitration. `ExpectedEventCount` and `ExpectedEventsSha256` bind the enumerated ordered list. They detect truncation/reorder when the originally recorded claims are kept fixed; a malicious recorder can fabricate new internally consistent claims, which only a Core-owned independently attested recorder/consumer can distinguish. `Choices` require explicitly named keys, a chosen canonical word present in unique allowed values and no duplicate keys; no implicit random seeding.

Hash encoding: SHA-256 uppercase hexadecimal. OriginalSourceSetSha256 is SHA-256 of the standard compact `System.Text.Json` UTF-8 serialization of ordered `BridgeDocumentDigestV1` rows. ExpectedEventsSha256 is SHA-256 of compact UTF-8 JSON of ordered event rows. ReplayIdentity hashes the compact UTF-8 JSON of **all** `GoldenRawTraceV1` properties in their declared order excluding ReplayIdentity. No timestamps or machine-specific paths; JSON is canonical, has no duplicate/unknown properties, and is byte-for-byte checked on reading. No normalization of lines, path case, source text, state/effect/choice order or signed bits. `ReadAndValidate` additionally requires an independently supplied current `BridgeSourceSnapshotV1` and assembly SHA-256; it does not trust the serialized hashes alone.

Limits: 4 MiB JSON, at most 512 steps, 128 events per step, 256 cells per collection, 32 nondeterministic choices per step, each choice 1..16 allowed bit patterns, 1..64 explicitly declared context/lane indices, <=32 MiB compiled assembly bytes. The source snapshot retains its own 128-document and source byte limits. Violations of raw trace structure return `Blocked` with HB4003/4004/4008 reason; invalid source/assembly identity or malformed JSON throws `ArgumentException` (fail closed). Cancellation is checked during capture and read; no arbitrary process to preempt and no runtime timeout guarantee is claimed.

## Migration and Core consumer

1. **No change** to `TrustedAddWordOracleV1` fixed `explicit-trusted-addword32/v1` adapter, to v1 vectors or to `BridgeSidecarCodecV1` schema/wire layout. Existing clients need no changes.
2. Optional new clients explicitly opt in to `golden-raw-trace/v1`, pin source snapshot and compiled assembly bytes independently, capture real host observations through a separately reviewed sandbox/recorder, and pass the resulting compact JSON through a strict reader. Do not treat the DTO's `Observed` as attested.
3. **CW-INT-10 Core-owned paired consumer/attestation PR required** before accepting these traces as an oracle. Core must bind the actual compiler closure/PE/PDB/source/method, sandbox/process limits, timeout, execution provenance, immutable playback, and distinguish forged fixture rows from real Golden transitions. **CW-INT-11** must independently run and attest native RTL simulation/formal/equivalence; missing pins, host isolation or actual tool runs remain `Blocked/NotRun`. Core still owns acceptance/gates and HWIR/RTL/EDA.
4. Processor timing/reset/stall/memory-port/arbiter/rank4 contracts and complete state/lane coverage are **Blocked** until explicit external contracts are qualified. The Bridge never extrapolates physical cycles or full CPU equivalence from a raw software step trace.
