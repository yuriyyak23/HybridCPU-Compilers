## Capture, generated sources and execution

`segmented_csc_capture_v2.py` and `SegmentedCscCaptureV2` use the separate HB raw capture schema `hybridcpu.hardwarebridge.csc-closure-index/v2`. Projection passes reviewed roots and selected bytes into the CW source-index domain. Original Csc command order, including generated syntax trees and references/analyzers/generators/options, travels through the reviewed capture map and observer evidence. Sorting output index rows by ordinal logical path cannot recover compile order. An evaluated MSBuild graph does not execute target-added items or generators. A task logger event does not prove file reads. Launch/response and source-byte witnesses bind their observed scope; a fresh independently reviewed replay and output match are separate claims. See [TaskTimeObserver](../../HWIR/EvaluatedProjectGraph/TaskTimeObserver/README.md), [CscLaunchProbe](../../HWIR/EvaluatedProjectGraph/TaskTimeObserver/CscLaunchProbe/README.md), [semantic inventory](../../SemanticInventory/README.md) and [executed link](../HB_INT_03_Executed_Csc_Link.md).

CircuitWeave also checks the [generated driver-order manifest](https://github.com/yuriyyak23/CircuitWeave/blob/66ffa4af96c3a8dbb1fb65f8cb8b31b1c3acae2c/src/CircuitWeave.Frontend.Roslyn/Bridge/CscGeneratedSourceOrderV1.cs) (`circuitweave.csc-generated-source-driver-order/v1`), pinned raw and staged capture identities, selected Csc profile, portable PDB and driver log. Rows bind exact captured bytes and UTF-8 source text after declared BOM removal in the reported driver order. Its captured-output profiles validate these rows and PE/PDB/refout/resource metadata before CWR3. A preflight import can succeed while execution and provenance remain `NotEstablished` and admission `NotAdmitted`.

V3 and V4 are explicit supplements, with distinct schema IDs and task-witness versions. Select the matching reader and independently pin both parent and supplement. V4 does not upgrade V2 source admission or V3 witness semantics. Digests for rows hash captured file bytes, descriptors pin exact manifest bytes, and closure hashes ordered raw JSONL chunks including LF. Duplicate properties, reordered canonical fields, invalid links/aliases, stale pins or forbidden roles fail under the respective codec/importer. The stage and artifact profile owns path materialization; validation assumptions are recorded with the receipt.

## Compatibility seams

- HB `BridgeSidecarCodecV1.ReadAndValidate` checks unique member names, the raw payload hash and required identities/statuses. CW requires exact key sets/order and full writer-canonical bytes. CW explicitly refuses Rejected facts with non-null compiler hashes (`CWINT03_REJECTED_HASH`). HB `Rejected(...)` constructs nulls, but its generic v1 `ValidFacts` does not enforce that rule for arbitrary Rejected DTOs. Use the stricter common profile and track the reader difference with the owners.
- Bridge v1 capture can represent an untokened generic selector and validates duplicate exact roots. CW v1 additionally rejects untokened generics and ambiguous overload combinations. Preserve the writer bytes and document the stricter consumer requirement. v2 provenance Candidate must establish instantiation semantics with the fields it actually carries. v1 generic selection does not justify projecting generic Candidate identities through v2.
- Full index SHA-256 pins roots and descriptors. Closure hash alone covers raw manifest bytes. A trusted caller supplies pin expectations independently of the package being parsed. Ordinal row sorting differs from Csc order and from case-insensitive collision checks. A producer accepting a virtual path in memory confers no rights to that path in a staged workspace.
- [CW independent re-emitter](https://github.com/yuriyyak23/CircuitWeave/blob/66ffa4af96c3a8dbb1fb65f8cb8b31b1c3acae2c/src/CircuitWeave.Frontend.Roslyn/RoslynIndependentBindingSourceVerifier.cs) owns exact supported Csc profiles, independent PE/PDB and typed graph comparisons. Successful import or reader byte parity grants only transport compatibility. Binding verification, source-derived HWIR, Accepted RTL and native proof each have independent consumers and gates.
- [TraceWeave reported DTO](https://github.com/yuriyyak23/TraceWeave-Studio/blob/ab9f3f577653c1dd616e284b8442d0f01f0ba25e/src/TraceWeave.Studio.Contracts/Compiler/ReportedCompilerFacts.cs) reads reported fields. CircuitWeave.Studio consumes downstream Core publications. Any cross-artifact link requires explicit artifact identity and digest-domain binding.
