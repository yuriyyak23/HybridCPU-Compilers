# HB-INT-03 — owned v2 workspace publisher (opt-in)

**Owner:** HardwareBridge / `SourceSnapshot`. Companion plan: [HB-INT-02 and HB-INT-03 in the six-package integration plan](CircuitWeave_Pipeline_Integration_Plan.md). Core ownership: CW-INT-03/04; hardware lowering, validation, verification and EDA remain Core-only.

**Status:** bounded software-source transport publication only. This is not Csc capture, a compiler, compiler-verification authority, Core source admission, RTL acceptance, or Processor proof. No Golden C#/Studio/Core files or existing v1/v2 JSON schema are modified.

## Concrete implementation

`BridgeV2WorkspacePublisher.Publish(outputDirectory, forbiddenSourceRoots, transport, roots, inputs, ct)` materializes the **existing** `circuitweave.bridge-source-closure-index/v2` into a completely new directory:

- `bridge-index/index.json` — exact canonical byte array generated by `BridgeSegmentIndexV2.Write`.
- `bridge-index/chunk-0000.jsonl`, etc. — exact raw chunk arrays with their existing SHA-256/row order.
- The indexed source, reference and supplied PE/PDB raw files at their safe, relative logical paths, with exact bytes/hashes from `BridgeV2Input`.

Before creating any filesystem entry, the publisher revalidates all supplied transport/index/chunks against **actual supplied byte buffers** using the existing Core-compatible v2 codec. It checks canonical safe paths, reserved index/chunk collisions, all source/library roots, and rejects a pre-existing output. The caller is REQUIRED to specify existing, non-symlink `forbiddenSourceRoots`: Golden root, parent compiler/Bridge checkout and Core checkout where applicable. A fresh staging sibling is created under an existing non-linked output parent. Each file uses `FileMode.CreateNew`; hashes of caller bytes and freshly written disk bytes are compared, source buffers are never modified, and files are re-read after staging. On successful checking, a same-volume `Directory.Move` exposes the output under its final name; otherwise staging is deleted and no destination is published. Cancellation checks are interleaved throughout.

`BridgeV2WorkspacePublication` returns `WorkspacePath, IndexSha256, ClosureSha256, FileCount, ChunkCount, InputBytes` — **transport diagnostics only**, not an authenticated receipt. Consumers must independently read and hash every staged byte, bind actual Csc/PE/PDB/reference/source/Git worktree identities, resolve exact symbols and enforce Core evidence gates. The publisher does not read or write original Golden files, execute Csc/MSBuild, synthesize or parse arbitrary C#, or create an EDA process.

The v1 `hybridcpu.hardwarebridge.sidecar/v1`, v2 source-index JSONL layout and opt-in `hybridcpu.hardwarebridge.provenance-index/v2` layouts remain byte-identical. This API does not change the default producer, schema, compiler project references or Core reader. **No paired Core PR is needed for the byte-identical transport format**; Core consumer integration still requires independent tests and agreed contracts.

## Example host call

```csharp
// Caller has already frozen exact Csc inputs and computed independent file pins.
// Host must not claim this is a live Golden capture without separately verifying it.
BridgeV2Transport snapshot = BridgeSegmentIndexV2.Write(roots, inputs, cancellationToken);
BridgeV2WorkspacePublication publication = BridgeV2WorkspacePublisher.Publish(
    outputDirectory: freshTempChild,
    forbiddenSourceRoots: new[] { goldenCheckout, bridgeCheckout, coreCheckout },
    transport: snapshot,
    roots: roots,
    inputs: inputs,
    cancellationToken: cancellationToken);
// publication.IndexSha256 and ClosureSha256 are software transport checksums ONLY.
```

`freshTempChild` must NOT exist, but its immediate parent must exist and must be outside the excluded source roots. Include every relevant source root explicitly; this API does not discover checkouts or infer ownership. Inputs must already be in memory and pin current upstream source bytes; this method does not validate a live source file against a Git ref. Always compare actual upstream Golden and Csc source hashes before **and after the entire export**, not merely before calling this publisher.

## Remaining limitations / blocked gates

- Caller-supplied roots are not authenticated; linked-ancestor checks and staging cannot eliminate malicious concurrent directory replacement (TOCTOU) on all hosts. Run only inside a permission-controlled isolated workspace; independently check every output in Core.
- Output publication is atomic at the directory rename, not a cryptographic attestation or durable crash-proof filesystem transaction. Cleanup failure may leave an **incomplete staging directory**, never a successful final destination.
- The v2 index is bounded (8,192 rows, 256 chunks, max 512 MiB raw buffers) and does **not** by itself qualify the full Csc invocation/generator closure. v1 snapshot still has its own smaller budgets.
- A real Golden clean/dirty worktree, source-before/after Csc capture and PE/PDB/SDK provenance remain **Blocked** pending qualified actual inputs. Native execution, independent RTL equivalence, processor memory/clock/rank4/lane6, FPGA/ASIC and Physical signoff remain **NotRun/Blocked**.
