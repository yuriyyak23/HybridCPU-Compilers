# Disposable Csc launch probe

This opt-in executable forwards a CscToolTask launch to an externally pinned compiler. The pinned executable path and SHA-256 must be supplied through `CW_CSC_PROBE_TARGET_PATH`, `CW_CSC_PROBE_EXPECTED_PATH`, and `CW_CSC_PROBE_EXPECTED_SHA256`; `CW_CSC_PROBE_LOG_DIRECTORY` names a writable directory. Each probe process creates a unique JSONL file without overwriting an existing file. The first record is flushed before child launch and records probe PID, UTC timestamp, its own `Environment.CurrentDirectory`, pinned tool path/hash and the exact argv received by the shim. The child inherits environment and standard handles, runs with that captured working directory, and receives each argument using `ProcessStartInfo.ArgumentList`. The result record links the child PID and exit code to the probe.

When `CW_CSC_PROBE_RSP_DIRECTORY` is supplied, the probe requires exactly one `@response` argument, opens that response file read-only with write/delete sharing denied, hashes and copies its bounded raw bytes, flushes a `response-snapshot` JSONL record, then holds the source handle until the child exits. This establishes which response bytes were stable at the path while the instrumented Csc child ran, not that Csc consumed or parsed those exact bytes. Missing/reparse/oversized response files fail before child launch.

Set `CscToolPath` to this executable's output directory and `CscToolExe` to `CscLaunchProbe.exe` only in a disposable, explicitly opted-in build. Set `UseSharedCompilation=false` so launches pass through the configured ToolTask path. The SDK's `Roslyn/Microsoft.CSharp.Core.targets` passes `CscToolExe` as `ToolExe` and `CscToolPath` as `ToolPath` to the Csc task; this probe does not change repository producer files.

Fail-closed behavior: missing environment values, unusable log directory, path mismatch, hash mismatch, launch failure, or log finalization failure returns a probe error; path/hash mismatch returns 126 without starting the child. If the initial durable log record cannot be created, the child is never launched. A final-record failure after launch returns 125, not the child's exit code; the first record still states the process was intended for observation. No read-buffer, response-file consumption, process-start completeness, cwd-at-file-access, or hardware claim is made.

`Tests` and `FixtureCsc` are fixture-only. They exercise Unicode/space working directories, argument fidelity, inherited stdout/stderr, child exit propagation, path/hash mismatch rejection and log-creation failure. Build and run them with `eng/run-csc-launch-probe-tests.ps1`; all output is directed to a unique TEMP directory.
